🛰️ Co dostajesz z API IMGW

Tak — z publicznego API dostajesz wiatr ze stacji, ale nie radial velocity radaru.

API `synop` zwraca prędkość i kierunek wiatru dla stacji naziemnych. To jest wiatr punktowy przy stacji. To nie jest pole prędkości radialnej z radaru Dopplera.

Najważniejsze rozróżnienie

Wiatr stacyjny = pomiar przy gruncie w jednym punkcie.

Wiatr radialny = składowa prędkości hydrometeorów wzdłuż wiązki radaru, piksel po pikselu.

Bez produktu VRAD/velocity z radaru nie zrobisz pełnej analizy inflow/outflow ani coupletu mezocyklonu.

Jak używać synopu do łowów

1. Weryfikacja outflow

Po przejściu gust frontu szukasz skoku prędkości, zmiany kierunku i spadku temperatury między sąsiednimi stacjami. To daje Ci naziemny podpis boundary.

2. Inflow quality

Przed wejściem komórki interesuje Cię, czy na E/SE od burzy utrzymuje się ciepły, wilgotny, uporządkowany napływ. Sieć stacji może potwierdzić, czy inflow nie został już podcięty.

3. Boundary hunting

Jeśli między dwiema stacjami masz wyraźny skręt wiatru i kontrast termiczny, to może być lokalna granica zbieżności albo strefa po outflow. To jest bardzo użyteczne pod nowe inicjacje.

4. Czego to nie zastąpi

Stacje nie pokażą Ci rotacji w objętości burzy, coupletu inbound/outbound ani tight gradientu velocity. Do tego potrzebujesz produktu radarowego Doppler VRAD.

❌ Nie z endpointów synop/meteo/hydro

Te endpointy API IMGW to dane stacyjne i ostrzeżenia. Nie są to wolumetryczne produkty radarowe Dopplera.

✅ Tak, ale z innych źródeł / innych produktów

Jeśli dorwiesz pliki radarowe single-site z produktem velocity/VRAD, wtedy masz prawdziwy wiatr radialny pikselowo. To może pochodzić z produktu radarowego, a nie z synopu.

🧠 Praktyka

Najmocniejszy workflow to połączenie: radar velocity + reflektywność + sieć stacji + obserwacje terenowe. Sama jedna warstwa zawsze ma luki.
